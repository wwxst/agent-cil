# Agent CIL 项目概览

## 1. 项目定位

Agent CIL V2 的目标是构建一个模型中立、事件驱动、可恢复，并具有强制执行安全边界的 Coding Agent Runtime。

它不是某一家模型 API 的薄封装，也不是照搬某个现有 Agent 项目的内部结构。它提供一套可由 CLI、Headless Worker 和 SDK 共用的任务执行内核。

~~~text
用户指令
  → Thread / Turn 生命周期管理
  → Agent Loop
  → Model Gateway
  → Tool Runtime
  → Execution Guard
  → 工具执行与结果提交
  → 下一次模型请求或 Turn 结束
~~~

## 2. 设计来源与取舍

V2 的设计参考以下方向：

- **Pi**：简洁的 Agent Loop、模型协议解耦和可替换工具。
- **Codex**：Thread / Turn 生命周期、审批控制、Sandbox 和执行可靠性。
- **DeepSeek Harness（DSH）**：追加式事件日志、状态投影、服务注册和扩展生命周期。
- **Agent CIL 的工程经验**：工具参数复验、授权重新判断、工具结果配对、取消和故障恢复。

这些是设计借鉴，不表示复制第三方代码，也不表示 Agent CIL V2 已经实现这些能力。

## 3. 主要目标

1. 一条用户指令对应一个可追踪、可恢复的 Turn。
2. 一个 Turn 可以包含多次模型请求、多个工具批次和审批暂停。
3. 每次工具副作用都能关联调用 ID、授权决定和执行记录。
4. 崩溃恢复能够区分未执行、已完成和结果未知的工具调用。
5. 切换 Provider 时保留必要的原生推理状态，不伪造跨 Provider 兼容。
6. Context Compaction 只改变模型上下文视图，不破坏完整事件历史。
7. CLI、Headless 和 SDK 使用同一套命令与事件契约。

## 4. 非目标

第一阶段不以以下能力作为交付前置条件：

- 多 Agent 自主协作和复杂编排。
- 分布式任务调度和跨机器 Exactly-once。
- 由插件动态替换 Session 状态机或权限执行入口。
- 完整复刻第三方 CLI 的私有协议或内部实现。
- 图形化 IDE、Desktop Renderer 或平台 UI。
- 未经基准测试就宣称 Coding 能力超过其他 Agent 系统。

## 5. 核心原则

### 单一事实来源

持久化事件是事实，内存 Session、消息数组和 UI 状态都是投影。任何可恢复状态都必须能从已提交记录重建。

### 小核心，明确边界

Agent Loop 只决定下一步做什么。模型请求、上下文准备、工具执行、授权、持久化和外部交互都通过明确接口完成。

### 安全策略不可选配

所有工具都经过统一执行入口。审批是用户意图确认，Sandbox 是操作系统或运行环境施加的实际限制，两者不能互相替代。

### 失败必须诚实表达

模型断流、工具拒绝、权限复验失败、进程崩溃和结果未知必须是不同状态。不能为了继续循环而把失败伪装成成功。

### 先验证可靠性，再优化性能

先建立状态提交、恢复、授权和副作用边界，再优化并发、流式预执行、缓存和调度吞吐。

## 6. 成功标准

V2 的成功不以目录拆分或代码行数衡量，而以以下结果衡量：

- 状态转换有明确契约和测试。
- 崩溃后不重复执行结果未知的副作用。
- 不同 Provider 通过同一套内部契约运行。
- Sandbox 能实际限制文件、进程和网络能力。
- 长任务在压缩和恢复后仍能维持工具调用连续性。
- 在相同模型、任务集和预算下，真实 Coding 任务成功率不低于既有基线。

详细指标见[验收标准](质量/验收标准.md)。
