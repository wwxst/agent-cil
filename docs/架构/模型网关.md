# Model Gateway：模型中立协议与 Provider Replay

## 1. 设计目标

Model Gateway 将 Agent Loop 与具体模型厂商、SDK 和传输协议隔离。

内部采用中立消息表示；Provider 边界保留必要的原生语义和不透明状态。支持多个 Provider 不等于把所有 Provider 的功能强行转换成同一种文本。

## 2. 内部响应模型

建议的基础类型：

~~~ts
interface ModelResponse {
  provider: string;
  model: string;
  blocks: ContentBlock[];
  toolCalls: ToolCall[];
  usage?: TokenUsage;
  stopReason: StopReason;
  providerState?: ProviderReplayState;
}

type ContentBlock =
  | { type: "text"; text: string }
  | { type: "tool_call"; callId: string; name: string; input: unknown }
  | { type: "reasoning"; visibility: "private"; providerData?: unknown }
  | { type: "image"; mediaRef: string }
  | { type: "data"; mediaType: string; ref: string };

interface ProviderReplayState {
  provider: string;
  modelFamily?: string;
  version?: string;
  opaque: unknown;
}
~~~

该模型是接口草案，不代表所有 Provider 都支持所有 Block 类型。

## 3. Provider Adapter 职责

每个 Adapter 负责：

- 将中立请求序列化为厂商 API 请求。
- 处理认证注入、流式解析、错误分类和取消。
- 将文本、工具调用、usage、stop reason 转换为中立事件。
- 保留厂商要求的原生推理状态、签名、缓存引用或回放数据。
- 对不支持的功能明确报错，不静默丢弃关键内容。

Core 不直接依赖任何厂商 SDK。

## 4. 首批协议范围

建议优先支持：

1. Anthropic Messages。
2. OpenAI Responses。
3. OpenAI-compatible Chat Completions。

协议适配和模型能力矩阵应分开。一个 API 协议可服务多个模型，但每个模型对 reasoning、tool calling、image、usage、cache 和 context window 的支持可能不同。

## 5. Provider-private Replay

`providerState` 不是 Thinking 文本的别名，也不是可以任意跨厂商转换的通用字段。

规则：

- 原生签名、加密或不透明推理数据必须原样保留。
- 只有匹配 Provider / model family / 兼容版本的 Adapter 才能解释并回放该状态。
- 不得把不透明推理数据改写成普通 text block。
- 切换 Provider 时必须定义明确的转换策略；不能安全转换的状态应作为能力边界暴露。
- 未知 Provider Block 不得在可能影响工具调用正确性的情况下静默丢弃。

## 6. Stop reason 与工具调用

工具调用事实以响应中的实际 tool call block 为准，stop reason 用于描述请求结束原因，不能在所有 Provider 中假设两者永远一致。

Adapter 必须验证：

- tool call ID 不重复。
- 参数 JSON 完整且符合约定。
- stop reason 在当前协议支持范围内。
- 工具调用和 Assistant 消息能够配对。
- 部分流失败时不会提交不完整消息。

## 7. 错误分类

至少区分：

- authentication / authorization；
- rate limit；
- transient transport；
- provider server error；
- invalid request / schema；
- context length exceeded；
- unsupported capability；
- stream interrupted / malformed stream；
- cancelled。

只有明确的、发生在响应开始前的 context length error 才可能触发压缩重试。任何已开始输出的流都不能默认安全重放，因为重放可能重复可见输出或工具动作。
