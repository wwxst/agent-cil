## 3. 证据等级

| 标签 | 含义 |
| --- | --- |
| 静态确认 | 在指定样本中找到可定位的实现或调用路径 |
| 历史报告 | 来自历史资料，本轮未重新执行 |
| Fixture 测试 | 在确定性本地 Fixture 或模拟服务上验证 |
| 真实服务测试 | 使用真实凭证连接真实 Provider 并完成指定验收 |
| 推断 | 根据结构或调用关系推断，仍需更直接证据 |
| 待验证 | 尚未验证 |
| 未知 | 现有材料不足以回答 |

## 4. 证据记录要求

每条验证记录应附：

- 被测 Commit；
- 操作系统和 Runtime 版本；
- Provider / Model / Endpoint（不含凭证）；
- 测试任务和工具权限；
- 结果、退出码和失败情况；
- 是否使用 Fixture 或真实服务；
- 是否有临时修改；
- 可复现的测试命令和脱敏日志位置。

## 5. 禁止的状态混淆

- 设计文档不等于实现完成。
- 静态代码观察不等于动态运行验证。
- 本地 Fixture 通过不等于真实 Provider 兼容。
- 旧版本或旧 Commit 的测试通过不等于当前版本通过。
- 单次真实服务测试不等于所有模型、平台和场景都已兼容。
- 不得用历史结果填补当前 Commit 的证据空白。
